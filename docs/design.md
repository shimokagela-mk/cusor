# 期练产品设计

微信小程序。给自己用，也给以后的其他人用。每个人只看自己的计划和记录。

一次使用的主线是：填写一个目标，生成长期计划，再自动拆成本周安排和今天要做的事。今天在同一页完成训练、饮食和体重打卡。

## 两类内容

用户在对话里定下来的，是小程序要完成什么。小程序算出来的数字、菜谱和训练内容，来自程序里写死的规则，不是用户逐项确认过的结论，也不是某位营养师或教练给这个人开的方案。

### 用户定的

- 一次计划只选减脂或增肌。两种都要有，同一份计划里不同时做。
- 计划要包含目标体重或目标体脂、总周期、阶段、每周训练天数、每日热量和三大营养素。
- 用户填目标，程序生成计划，不手动画课表。
- 同时给出四餐菜谱，以及当天热量和三大营养素额度。实际摄入另行记录，用来和额度对比。
- 食物记录包含名称、份量、热量、蛋白质、碳水、脂肪。家常菜、外卖、健身餐都要能记。
- 录入要方便，并且结果能核对、能改。拍照识别错了可以改名称和份量。
- 训练记录动作、组数、次数、重量，并有动作库、组间计时和当天清单。
- 每日打卡是训练、每一餐和体重。体围和身材照片不做。
- 没完成的日子标未完成，后续日期不顺延。改期由用户手动处理。

用户没有指定热量公式、阶段怎么切、蛋白质按每公斤多少克、菜怎么配、动作用哪一套。这些是实现时补上的规则，来源写在下一节。

### 程序给出的结果从哪来

程序不读取用户的体检、饮食史或外部营养数据库。它只用制定计划时填的那几项，套下面这套固定规则。

| 结果 | 来源 |
| --- | --- |
| 基础代谢 | Mifflin-St Jeor 公式：`10 × 体重 + 6.25 × 身高 − 5 × 年龄`，男性再 `+ 5`，女性再 `− 161`。这是公开发表的估算公式，用的是用户填的性别、年龄、身高、体重。 |
| 维持热量 | 基础代谢乘活动系数。系数按每周训练天数套用常见活动分级：1 天及以下 1.2，2–3 天 1.375，4–5 天 1.55，6–7 天 1.725。训练天数不等于全天活动量，这一步是近似。 |
| 每日热量 | 维持热量乘阶段系数。减脂三段是 0.88、0.80、0.82；增肌三段是 1.08、1.12、1.08。系数是实现时取的固定值，落在常见的大约 10%–20% 缺口或盈余里。目标体重不参与这个乘法，只用来判断变化是否过快并给出文字提示。 |
| 蛋白质 | 当前体重乘固定比例：减脂 2.0 克/公斤，增肌 1.8 克/公斤。 |
| 脂肪 | 当前体重乘固定比例：减脂 0.8 克/公斤，增肌 0.9 克/公斤。碳水过低时，脂肪最低降到 0.6 克/公斤。 |
| 碳水 | 用当天热量减去蛋白质和脂肪的热量后，按每克 4 千卡换算。 |
| 阶段长度 | 总周数分成三段，除不尽的周数先分给第二段，再分给第三段。阶段名称是适应期、强化期或增量期、巩固期。 |
| 训练分化 | 按每周天数使用固定模板：全身，推拉腿，或上下肢。见下文表格。 |
| 动作、组数、次数、休息 | 手写动作库。按目标、经验、是否最后一周减量来定组数和休息。避开用户选的伤病，以及当前没有的器械。 |
| 菜谱和食物热量 | 手写食物表，每 100 克写有热量和三大营养素；手写早中晚加餐模板。模板按该餐额度缩放克数。这些数字是编写时填入的常用值，不是从《中国食物成分表》或 USDA 导入的。 |
| 拍照识别 | 默认只在手写食物表里按菜名或别名匹配。没有接入能看懂照片的模型。 |

因此，同一组填写内容每次会得到同一份计划。换一个人，只要填写数字不同，结果就不同；规则本身不变。

## 先不做

- 社区、排行榜、教练代学员排课。
- 同一份计划里同时减脂又增肌。
- 未完成自动顺延。
- 体围、身材照片。
- 把照片直接当成已经识别正确的结果。未接入图像服务时，只根据用户确认的菜名匹配食物库。

## 谁在用

一个人制定自己的计划并每天打卡。多人使用时，每个用户的计划、饮食、体重和训练记录互相隔离。

第一版数据保存在当前设备。换手机不会自动同步。正式发布时再接入微信登录和云端存储，页面流程不变。

## 页面

底部四个页签。

| 页签 | 作用 |
| --- | --- |
| 今日 | 今天的阶段、额度、体重、训练和四餐打卡 |
| 本周 | 周一到周日的训练与热量额度，进入某一天，调换训练 |
| 计划 | 整个周期、三个阶段、每周节奏 |
| 我的 | 当前用户、切换用户、体重趋势、动作库、重新制定计划 |

从今日或计划进入「制定计划」。从今日进入某一餐的搜索、手填、拍照，以及训练打卡。从本周进入任意一天，过去的日子可以补记，还没到的日子只能查看。

## 制定计划

分五步，每步校验通过才进入下一步。

1. 主目标：减脂或增肌。
2. 身体：性别、年龄、身高、当前体重。当前体脂可以不填。
3. 目标：目标体重或目标体脂至少填一个，加上周期周数。
4. 训练：每周哪几天能练、新手或有训练经验、健身房或居家。居家再选哑铃、弹力带、引体向上杆。自重始终可用。
5. 限制：膝盖、腰、肩、手腕；素食、不吃海鲜、不吃猪肉、不吃牛肉、乳糖不耐、不吃辣。都可以不选。

年龄 16–80，身高 120–230 厘米，体重 30–250 公斤，周期 4–52 周。生成从当天开始，覆盖整个周期。重新制定会替换当前用户的计划，已经记下的日志按日期保留。

生成后的计划页展示目标、起止日期、三个阶段的每日额度、周一到周日的训练节奏。如果目标体重要求的每周变化快于常见范围，页面写明热量仍按较稳妥的速度安排，周期结束时体重可能达不到目标。

## 计划怎么生成

计算步骤和每一项的来源见上一节。下面只记规则本身。这是安排用的估算，不是医疗建议。目标体重或目标体脂不改变每日热量，热量只由维持热量和阶段系数决定。

周期分成三段，余数优先分给中段和后段。

| 阶段 | 减脂 | 增肌 |
| --- | --- | --- |
| 第一段 | 适应期，缺口较小 | 适应期，盈余较小 |
| 第二段 | 强化期，缺口加大 | 增量期，盈余加大 |
| 第三段 | 巩固期 | 巩固期 |

周期不少于两周时，最后 7 天减少训练组数。

训练日就是用户选中的星期。其余日子为休息，仍然保留饮食额度和体重打卡。

| 每周天数 | 安排 |
| --- | --- |
| 1–2 天 | 全身 |
| 3 天 | 新手全身；有经验则推、拉、腿 |
| 4 天 | 上肢、下肢交替 |
| 5 天 | 推、拉、腿、上肢、下肢 |
| 6 天 | 推、拉、腿循环 |
| 7 天 | 推、拉、腿、上肢、下肢、全身、推 |

动作从动作库里选，并避开伤病和当前没有的器械。主要复合动作在各周保持稳定，孤立动作按周轮换。新手每次约 4 个动作，有经验约 5 个。可选动作不够时，用仍能完成的动作；一个都没有时，当天改为快走。

每日饮食额度按早餐 25%、午餐 35%、晚餐 28%、加餐 12% 拆开。每一餐从符合忌口的菜谱里选择，并按该餐额度调整份量。菜谱覆盖家常、外卖、健身餐。蛋白质不足时，在忌口允许的前提下补一份蛋白食物。

## 今日打卡

一天完成需要三件事：

- 记下体重大于 0。
- 四餐都有记录，或被明确标成「不吃这餐」。
- 训练日完成全部组，或标记整次训练完成。休息日不要求训练。

状态：

- 今天未完成：进行中。
- 今天已完成：已打卡。
- 过去未完成：未完成。
- 未到的日期：未到，不能打卡，可以查看菜谱和训练。

每一餐同时显示建议菜谱和实际记录。实际记录的热量和三大营养素汇总后，与当天额度对比。按菜谱记入会把建议食物抄进实际记录，之后仍可改份量或删除。

训练页列出动作、组数、次数、建议休息时间和要点。完成一组后开始休息计时。若这个动作以前记过重量，显示上次重量。

## 改期

在本周页把某一天的训练和另一天对调。对调的是训练内容和已记下的组数，饮食额度和当天其他记录留在原日期。对调之后的日子不整体后移。

## 饮食记录

搜索按名称和别名匹配。手填需要名称、克数、热量和三大营养素。最近吃过保留最近 12 项。

拍照流程：

1. 选择照片。
2. 输入看到的菜名，或从候选里点选。
3. 确认克数后记入这一餐。

配置了识别服务时，照片和菜名会发给该服务；服务返回的结果仍要用户确认。没有配置时，不把照片解释成自动识别结果。

## 动作库

动作库列出名称、部位、所需器械、动作要点，以及哪些伤病会避开它。有计划时可以只看当前器械和伤病下能做的动作。

## 多个用户

「我的」里可以修改昵称、新建用户、切换用户。切换后，今日、本周和计划都只显示该用户的数据。

## 验收

- 只选减脂或只选增肌，都能生成完整周期。
- 计划里同时看得到阶段、每周训练、每日营养额度和四餐菜谱。
- 忌口食物不会出现在菜谱里；伤病和缺少的器械不会被排进训练。
- 今日可以记体重、训练和四餐，并看到实际摄入和额度的差异。
- 漏打卡的日期保持未完成，后续日期和训练内容不变。
- 手动调换只交换两天的训练。
- 两个用户的计划和记录互不可见。
