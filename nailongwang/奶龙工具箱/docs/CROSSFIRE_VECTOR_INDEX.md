# shujuku 交火模式与纪要向量索引速查

交火模式是 shujuku 的远记忆/纪要索引增强链路。它和普通向量模式共享部分向量能力，但目的不是简单地“开向量搜索”，而是围绕纪要索引、关键词生成和召回组织上下文。

## 适合什么时候看

- 用户问“交火模式是什么”。
- 关闭交火后普通向量还在跑。
- 交火召回不到旧剧情。
- 关键词生成不稳定。
- 纪要索引、向量缓存、世界书注入混在一起说不清。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 交火模式 | 针对纪要索引的增强召回链路 |
| 普通向量模式 | 常规远记忆向量召回 |
| 纪要索引 | 从聊天/纪要中拆出的可召回片段 |
| 关键词 prompt group | 用最近上下文生成检索关键词 |
| summary prompt group | 用于纪要摘要/索引相关处理 |
| rerank | 对召回结果再排序 |
| hot cache / temp cache | 索引与片段的缓存层 |

## 与普通向量的关系

交火模式会复用普通向量的模型、API、rerank 等配置。因此开启交火时，普通向量能力可能被同步启用。

重要边界：

- 交火模式关闭时，应同步关闭普通向量 `enabled`，避免用户以为退出交火后普通远记忆仍继续跑。
- 关闭只应改 `enabled`，不应清空模型、endpoint、API key、rerank、namespace 等配置。
- 交火和普通向量不是两个完全隔离的配置岛。

## 常见排错

### 关闭交火后仍在走向量

判断：

- 检查交火开关是否关闭。
- 检查普通向量 `enabled` 是否仍为 true。
- 检查发送前分流是否落回普通 vector preprocess。

处理：

- 关闭交火时同步关闭普通向量 enabled。
- UI 上普通向量 checkbox 和配置块也要同步刷新。

### 交火召回不到旧剧情

检查：

- 当前聊天是否已有纪要索引。
- 索引是否过旧，需要重建。
- 关键词生成 prompt group 是否为空或过弱。
- rerank 配置是否不可用。

### 关键词过宽或过窄

检查：

- keyword prompt group 是否明确要求输出检索关键词。
- 最近上下文是否太短。
- 是否把表格字段、人物名、地点名作为关键词保留下来。

## 工具箱写法建议

当用户只是问交火机制，输出“机制 + 排错清单”，不要直接改配置。

当用户要写前端按钮或脚本控制交火，应回到 `window.AutoCardUpdaterAPI` 公开 API；如果公开 API 没暴露对应开关，不要建议直接改内部 storage。

当用户要调索引质量，应优先检查：

1. 最近剧情上下文。
2. 关键词 prompt group。
3. 纪要摘要质量。
4. 向量模型与 rerank 配置。
5. 索引是否刷新。
