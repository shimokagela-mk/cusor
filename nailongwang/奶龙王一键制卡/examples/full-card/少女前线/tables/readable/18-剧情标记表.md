## 说明

- 记录会影响主线走向的关键剧情分岔标记。
- 本表只保留 `标记名称` 和 `是否触发` 两列。
- `是否触发` 只能填写 `是` 或 `否`。
- 默认全部为 `否`；当正文明确发生对应事件时，填表 AI 才能改为 `是`。
- 任一标记为 `是` 时，表示剧情正在偏向或进入对应历史线风险；全部保持 `否` 时，表示这些关键悲剧尚未发生，剧情仍保留完美线空间。
- 填表 AI 不得新增、删除或替换本表四个核心标记。
- 前端可以读取本表判断剧情路线提示，但不应直接修改本表。
- 【列定义】
- 列1=标记名称：关键剧情转折标志名称，固定四行，不得改名。
- 列2=是否触发：该关键剧情转折是否已经发生，只能填写 `是` 或 `否`。

## 更新规则

- 初始化: 按当前内容初始化四个核心剧情分岔标记，所有 `是否触发` 均为 `否`。
- 更新: 允许填表 AI 根据最新正文和当前章节 `<战役>...</战役>` 内容将明确发生的标记更新为 `是`；不得凭推测提前判定。
- 插入: 禁止 AI 插入。新增分岔标记只能由维护者手工添加并同步剧情规则。
- 删除: 禁止。四个核心剧情分岔标记不得由 AI 删除。

## DDL

```sql
CREATE TABLE story_flags ( -- 剧情标记表
  row_id INTEGER PRIMARY KEY, -- 行号
  flag_name TEXT NOT NULL UNIQUE, -- 标记名称
  is_triggered TEXT NOT NULL CHECK(is_triggered IN ('是','否')) -- 是否触发
);
```
