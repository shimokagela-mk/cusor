# 人物设计 Prompt 拆分说明

`4-人物设计.md` 是入口路由，不承载完整执行规则。实际执行按阶段读取：

```text
4-人物设计.md
        │
        ▼
4-1-人物设计-自述阶段.md   ← 凉宫春日引导，做角色自述（核心是"怎么写好自述"）
        │
        │  用户确认定稿角色自述
        ▼
（可选）4-3-人物设计-润色.md  ← 想打磨文字才进，满意可跳过
        │
        ▼
4-2-人物设计-语料阶段.md   ← 四声部语料 + 写入
        │
        ▼
人物设计完结
```

## 为什么拆

自述阶段和语料阶段关注点不同：自述解决"角色是谁"，语料解决"角色怎么说话"。自述没定稿前不需要加载语料规则，提前加载只会互相干扰。所以拆开，按阶段读。

文字润色单独拆成可选的 `4-3`，是因为它属于"事后打磨"——自述阶段应专注"把角色写明白"，不该被全局文风纪律分心。草稿满意时润色可以整段跳过。

## 文件分工

| 文件 | 内容 | 读取时机 |
| --- | --- | --- |
| `4-人物设计.md` | 入口路由与阶段边界 | 进入人物设计时先读 |
| `4-1-人物设计-自述阶段.md` | 自述理念、写法、避雷、流程、定稿自检 | 默认第一执行阶段 |
| `4-3-人物设计-润色.md`（可选） | 自述文字润色（去翻译腔、清残留八股） | 自述定稿后、用户想打磨文字时 |
| `4-2-人物设计-语料阶段.md` | 四声部语料、人物条目模板、写入 | 自述已定稿后读取 |

## 产物关系

- 角色自述 → 角色卡 `personality` 字段，解决"AI 知道我是谁"。
- 四声部语料 → 世界书人物条目，解决"AI 知道我怎么说话"。
- 两者缺一不可。
