# 剧情推进预设提示词

## 这个文件负责什么

当组件规划已经确认“需要剧情推进预设”时，使用本文件。

本文件只负责：

- `frontend/剧情推进.json`

如果还没有确认组件结构，先回到：
- `prompts/7-开场白状态栏讨论.md`

如果要做的是推进美化 HTML 与推进正则配置，改去：
- `prompts/7-4-剧情推进前端.md`

---

## ⚠️⚠️⚠️ 最高优先级规则：开始前必须先阅读本文件与范例 ⚠️⚠️⚠️

在讨论或生成剧情推进预设之前，必须先阅读：

1. `prompts/7-3-剧情推进预设.md`
2. `examples/full-card/少女前线/entries/999-ACU-表格模板.yaml`
3. `examples/full-card/少女前线/frontend/opening-regex.html`

### 阅读目标

- 学习表格模板如何通过世界书条目承载 base64 数据
- 学习开场正则如何从世界书读取数据并初始化
- 学习剧情推进预设如何逐步沿用同一种世界书注入链路，而不是只写一句“仿照表格”
- 学习 recall 相关字段的语义
- 学习 `extractTags` 应如何定义
- 学习“预设本体先正确，再谈展示层”的优先级

### 禁止行为

1. ❌ 禁止不读范例就直接写 `剧情推进.json`
2. ❌ 禁止让推进美化层反向定义 recall 规则
3. ❌ 禁止把预设拆成另一套自创 schema
4. ❌ 禁止没有正确对象反馈时仍然强行填充 `<recall>`
5. ❌ 禁止只把预设 Base64 写在前端 HTML 里，必须规划世界书注入条目
6. ❌ 禁止保留 `{{PRESET_BASE64}}` 或任何前端备用注入方式

---

## 阶段目标

与用户确认并完成：

1. 是否真的需要剧情推进预设
2. 预设要承担哪些用途
3. recall 规则如何定义
4. `extractTags` 如何规划
5. 最终形成固定格式的 `frontend/剧情推进.json`
6. 预设数据使用哪个世界书 key 承载，并由开场正则读取注入

---

## 什么情况下需要剧情推进预设

只要用户有以下任一需求，就应考虑启用：

- 正文前额外推进
- 最终注入替换
- 额外 DM 判定
- 规则判定辅助
- 需要结构化推进结果供前端美化消费

如果用户只要普通世界书和普通状态栏，且没有上述链路，可以不做。

---

## 核心优先级：预设本体高于展示层

### 强制规则

- 先把 `剧情推进.json` 做对
- 再去做 `推进美化.html` 与 `推进正则配置.json`
- 展示层只能消费已经正确产出的标签
- 展示层不能倒逼预设层改语义

### 绝对禁止

- ❌ 为了让美化界面好看，回头改 recall 逻辑
- ❌ 在预设没有正确定义前，先做推进前端
- ❌ 用推进美化层掩盖预设本体错误

---

## recall 规则是本文件的最高重点

### 必须保留 recall 相关字段

例如：
- `recallCount`
- `extractTags`
- 以及范例结构中的相关召回定义位

### `zhaohui` 的语义

`zhaohui` 必须视为：

- **召回数量的数字占位符**
- 不是标签名
- 不是文本装饰词
- 不能写成“zhaohui条”这种易混淆表述

### 推荐固定表述

```text
召回zhaohui数量的总结条目；若不足则按最大可召回条数处理
```

### recall 的固定语义

1. 只从正确对象反馈中提取编码
2. 背景设定、前文剧情、上轮规划只用于理解局势
3. 这些上下文不能直接作为 recall 编码来源
4. 如果没有正确对象反馈，`<recall>` 必须明确留空
5. 即使给了数字，也不能为了凑数量去补造内容

---

## `extractTags` 规划规则

### 作用

`extractTags` 是后续推进前端展示层要消费的标签清单。

### 要求

1. 必须显式列出
2. 必须和预设实际输出一致
3. 不要写一堆不会实际产出的标签
4. 不要把展示层想要的标签硬塞给预设层

### 原则

- 先想清楚预设真正会输出什么
- 再把这些东西列为 `extractTags`
- 后续推进前端只能围绕这些标签去美化

## 与开场白、推进前端的关系

## 剧情推进预设的世界书注入流程（必须照做）

剧情推进预设必须像少女前线表格模板一样，通过世界书条目承载，再由开场正则读取。不要让执行者自行猜测实现方式。

1. 预设源文件：`frontend/剧情推进.json`。
2. 世界书条目文件：默认创建 `entries/998-ACU-剧情推进预设.yaml`。
3. 条目 comment：`AutoCardUpdater 剧情推进预设（勿删勿改）`。
4. 条目 content：`frontend/剧情推进.json` 的 JSON 文本经 UTF-8 base64 编码后的字符串。
5. 条目 keys：必须包含 `__ACU_PRESET_DATA__`。
6. 条目建议配置：`constant: false`、`selective: false`、`position: before_char`、`insertion_order: 998`、`depth: 2`、`prevent_recursion: true`、`use_regex: false`。
7. 开场正则点击开始时先读取 `__ACU_TEMPLATE_DATA__` 得到 `templateData`，如启用预设，再读取 `__ACU_PRESET_DATA__` 得到 `presetData`。
8. 两者都用同一个 UTF-8 base64 解码函数转成 JSON。
9. 初始化表格 + 预设时调用：

```javascript
await api.initGameSession({}, {
  injectTemplate: true,
  templateData,
  loadPreset: true,
  presetData
});
```

10. 未启用剧情推进预设时，不创建 `998-ACU` 条目，不读取 `__ACU_PRESET_DATA__`，初始化参数保持 `loadPreset: false`。

---

### 与开场白前端的关系

如果开场白需要在开始按钮中一并注入预设：
- 预设必须先定稿
- 必须先规划预设世界书条目，例如 `__ACU_PRESET_DATA__` 或项目约定 key
- 开场正则必须像少女前线读取 `__ACU_TEMPLATE_DATA__` 一样读取该 key
- 再去做 `opening-regex.html`

### 与推进前端的关系

推进前端必须建立在预设已经定稿的基础上：
- 先定 `extractTags`
- 先定 recall 规则
- 再做美化与 cleanup 配置
